# コンテナのセキュリティ設計

`scripts/` のコンテナがセキュリティのために従う方針を定めます。
新しいイメージを追加するときもこの方針に従い、従えない箇所は理由を Dockerfile か `compose.yaml` のコメントに残します。

## 守る対象

外部のツールは、本体や依存に悪意のあるコードが混入している可能性があります。
混入していても被害が広がらないよう、次のものをツールから守ります。

- AWS の認証情報、State、`.tfvars` などの手元の値
- ホスト上のファイルの内容
- ホストの CPU、メモリ、プロセス数

そのため、ツールは何も持たない状態から始め、必要な権限だけをサービスごとに与えます。

## ネットワーク

実行時のネットワークは `network_mode: none` で遮断します。
ツールが必要とするものは、次のように通信なしで用意します。

- 実行に必要なプラグインやデータは、ビルド時にイメージへ入れる
- Go のモジュールのように手元にあるものは、読み取り専用でマウントする
- ツール自身の更新の確認や通信を伴う機能は、設定で止める

### 通信が欠かせないサービス

Terraform の `aws` と `lock` は通信が欠かせないため、許可リストを持つ forward proxy だけを経由させます。

- ツールは `internal: true` のネットワークだけに接続する。外へ出る経路がないため、ツールが `HTTPS_PROXY` を無視しても直接は通信できない
- proxy だけが internal と egress の両方のネットワークに接続する
- 許可リストが混ざらないよう、proxy とネットワークは用途ごとに分ける
- 許可リストにはホスト名を完全一致で書き、AWS の宛先はリージョンまで絞る
- proxy は 443 番ポートへの `CONNECT` だけを通す。TLS は復号せず、キャッシュも持たない
- 宛先の IP アドレスの逆引きを止める。逆引きすると、PTR レコードを許可リストの名前にした IP アドレスを通してしまう
- 実行後に proxy のログを出力し、通信した宛先を確認できるようにする

## 実行ユーザー

実行ユーザーは原則として `65534:65534` とし、root もホストのユーザーも使いません。

- Dockerfile の最後の `USER` と `compose.yaml` の `user` の両方に指定する。`compose.yaml` を介さずにイメージを実行しても root にならない
- イメージに入れるファイルは、実行ユーザーが読めて、書き換えられない権限にする
- `65534` には書き込めるホームディレクトリがないため、`HOME` を `/tmp` に向ける

## ファイルシステム

ルートファイルシステムは `read_only: true` にし、書き込み先を明示したものに限ります。

- 一時ファイルは `/tmp` の tmpfs に置き、`noexec,nosuid,nodev` とサイズの上限を付ける
- ホストのディレクトリは bind mount で渡し、`read_only: true` を基本にする
- マウントする範囲は、ツールが必要とするディレクトリまで絞る。Alloy にはリポジトリのルートではなくモデルのディレクトリだけを渡す
- 書き込みが必要な処理は、読み取りだけの処理とサービスを分ける。`fmt-check` は読み取り専用で、`fmt` は `terraform/` に書き込む
- ツールの設定ファイルは、検査対象の外の `/config` に読み取り専用でマウントし、起動時の引数で指定する

### 機密ファイルの隠し方

リポジトリのルートのように広い範囲を渡すときは、不要なパスをコンテナから隠します。

- ディレクトリは、読み取り専用の空の tmpfs で覆う
- tmpfs で覆えないファイルは、`/dev/null` を重ねる
- 読み取り専用の `/src` にはマウントポイントを作れないため、Makefile がホスト側に用意する

隠すパスは `.gitignore` と連動せず、列挙していないものはコンテナから読めます。
そこで機密ファイルの置き場所を `tmp/` と `terraform/local/` に定め、`terraform/` の中でほかの場所に置かれたものを Makefile の `tf-misplaced-values` で検出します。
隠すパスを追加するときは、golangci-lint と trivy の `compose.yaml`、Makefile の `container-mountpoints` をそろえて変更します。

## プロセスの権限と資源の上限

すべてのサービスに次の設定を入れます。

| 設定 | 目的 |
|---|---|
| `cap_drop: [ALL]` | Linux capability をすべて外す |
| `security_opt: ["no-new-privileges:true"]` | setuid などによる権限の昇格を防ぐ |
| `ipc: none` | 専用の IPC 名前空間を持たせ、`/dev/shm` をマウントしない |
| `ulimits: { core: 0 }` | メモリの内容をコアダンプとして残さない |
| `init: true` | シグナルの転送とゾンビプロセスの回収を init に任せる |
| `mem_limit` と同じ値の `memswap_limit` | メモリの上限を決め、スワップで超えさせない |
| `pids_limit` | プロセスの増えすぎを止める |
| `cpus` | CPU の使用量を抑える |

上限の値は、ツールごとに必要な分だけ割り当てます。
Makefile からは `docker compose run --rm -T --interactive=false` で実行し、TTY と標準入力を渡さず、終了したコンテナを残しません。

## 認証情報の渡し方

認証情報は、必要なサービスの環境変数にだけ渡します。

- 認証情報と外部のコードの取得を、同じプロセスに持たせない。`lock` は Provider を取得するが AWS の認証情報を持たず、`aws` は認証情報を持つが Provider をイメージの中からしか読まない
- 値は `compose.yaml` やイメージに書かず、シェルから引き継ぐ
- 一時的な認証情報だけを受け付ける。Makefile が `AWS_SESSION_TOKEN` を必須にし、長期のアクセスキーでは起動できない

`${VAR:?}` はファイル全体の展開で評価されるため、一部のサービスだけが使う認証情報に使うと、ほかのサービスまで起動できなくなります。
そのような値の確認は Makefile で行います。

## イメージとビルド

ビルドはネットワークと root を使えるため、取り込むものを固定して検証します。

- ベースイメージと `# syntax=` はタグと digest で固定し、ベースイメージのレジストリも省略せずに書く
- 手元でビルドするイメージは `localhost/` を付け、`pull_policy: never` にする。レジストリにある同名のイメージを取得しない
- 公式イメージに追加するものがなければ Dockerfile を作らず、digest で固定して直接使う。golangci-lint がこれにあたる
- `.dockerignore` は `*` ですべて除外してから、ビルドで使うファイルだけを許可する。ビルドコンテキストに手元の値を渡さない

ビルド時に取り込むものの検証手段は次のとおりです。

| 取り込むもの | 検証の手段 |
|---|---|
| Terraform の Provider | `.terraform.lock.hcl` のハッシュ |
| tflint の AWS ruleset | リリースの `checksums.txt` の値を Dockerfile に固定する |
| Alloy の JAR | リリースにハッシュの公開がないため、取得した JAR から計算した値を固定する |
| squid | バージョンを Dockerfile に固定し、内容は Alpine のパッケージの署名で検証する |
| Z3 | バージョンを Dockerfile に固定し、内容は Debian のパッケージの署名で検証する |
| bats の jq | リリースの `sha256sum.txt` の値を、アーキテクチャごとに Dockerfile に固定する |
| bats のベースイメージの Alpine のパッケージの更新 | 修正された脆弱性を取り込むため版を固定せず、内容は Alpine のパッケージの署名で検証する |
| trivy の脆弱性 DB とチェック | 内容が更新され続けるため固定せず、`make trivy-update` の再ビルドで更新する |

## 方針から外れるサービス

次のサービスは、機能に必要なため方針から外れます。

| サービス | 方針から外れる点 | 理由 |
|---|---|---|
| Terraform の各サービス | ホストの UID と GID で実行する | State と lock ファイルを運用者のファイルとして残すため |
| `offline`、`aws`、`lock` | `terraform/local/` に書き込める | State、Plan、`.terraform/` の置き場所のため |
| `lock` | `terraform/` に書き込める | lock ファイルを更新するため |
| `lock` | `TMPDIR` が `terraform/local/` を指す | 全プラットフォームの Provider の展開が `/tmp` の tmpfs に収まらないため |
| `fmt` | `terraform/` に書き込める | フォーマットの結果を書き戻すため。`terraform/local/` は覆う |
| `proxy-aws`、`proxy-lock` | `ipc: private` を使う | squid が起動時に `/dev/shm` の共有メモリを作るため |

## この設計で防げない攻撃

- 許可リストの宛先を使った持ち出し。通信の中身は検査しないため、たとえば別の AWS アカウントの認証情報で `logs` の宛先へデータを送る通信は止まらない
- コンテナに渡した認証情報の悪用。そのコンテナのプロセスは認証情報を読めるため、被害は認証情報の権限と有効期限の範囲に収める
- 書き込み可能なマウントの改ざん。ホスト側のファイルをコンテナから書き換えられる
- 取り込み元の汚染。trivy の DB と bats のベースイメージの Alpine のパッケージの更新は内容を固定せず、squid と Z3 はハッシュを固定しないため、取得元を信頼している

## イメージを追加するときの確認項目

- [ ] 実行ユーザーを Dockerfile と `compose.yaml` の両方で `65534:65534` にした
- [ ] 「プロセスの権限と資源の上限」の設定をすべて入れた
- [ ] `read_only: true` にし、`/tmp` の tmpfs に `noexec,nosuid,nodev` とサイズの上限を付けた
- [ ] bind mount の範囲を必要なディレクトリまで絞り、読み取り専用にした
- [ ] 広い範囲を渡す場合は、機密ファイルのパスを隠した
- [ ] `network_mode: none` にし、必要なものをビルド時に入れ、ツールの通信を設定で止めた
- [ ] 通信が欠かせない場合は、用途専用の proxy と internal ネットワークを用意した
- [ ] 認証情報を渡すサービスでは、外部のコードを取得しないようにした
- [ ] ベースイメージを digest で固定し、ダウンロードするものをハッシュで検証した。パッケージマネージャーで入れるものはバージョンを固定した
- [ ] 手元でビルドするイメージに `localhost/` と `pull_policy: never` を指定した
- [ ] `.dockerignore` を許可リストの形にした
- [ ] 方針から外れる箇所に理由のコメントを残した

実装の参考には、構成の近い既存のイメージを使います。

| 構成 | 実装 |
|---|---|
| 最小の構成 | `scripts/alloy/` |
| データをイメージに持ち、機密ファイルを隠す構成 | `scripts/trivy/` |
| 通信の許可リストと認証情報を分離する構成 | `scripts/terraform/` |
